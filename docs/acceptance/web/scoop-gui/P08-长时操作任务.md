## 1. 验收范围

覆盖软件包安装、卸载、更新、桶添加/移除、协助安装 Scoop 的任务记录。本文验证任务行为，不限定任务信息的导航位置、窗口形态、分栏方式或列表布局。

## 2. 创建与状态

| 场景 | 操作 | 预期结果 |
| --- | --- | --- |
| 单个长时操作 | 发起任一受支持操作 | 创建一条关联目标对象的任务,用户可查看其动作、目标、状态与日志 |
| 批量卸载或更新 | 确认 N 个目标 | 为每个目标创建独立任务;每项状态、取消和结果互不覆盖 |
| 状态变化 | 等待队列执行 | 任务按既定顺序从排队中进入执行中,最终成为已成功、已失败(可重试)或已取消 |
| 多种终态并存 | 产生成功、失败、取消任务 | 各终态有清楚且不只依赖颜色的区分;取消不得显示为失败 |
| 空任务集合 | 尚未发起操作 | 明确表示暂无任务,不伪造任务或错误 |
| 失败后再次操作 | 从来源功能重试 | 创建新任务并保留原失败记录;失败任务本身不被复用 |

## 3. 进度、日志与取消

- 活跃任务应能让用户判断操作仍在排队或执行;不得臆造 Scoop 未提供的百分比进度。
- 用户可查看与具体任务关联的原始诊断日志;日志不得与其他任务串扰,也不得因界面语言切换而被翻译。
- 用户可取消排队中或执行中的任务;成功取消后记录为“已取消”,并按业务流程恢复目标对象的操作前状态。
- 取消已成功、已失败或已取消的任务不应被允许;取消失败时不得伪报为已取消。
- 用户离开任务信息后,后台任务继续运行;之后可再次查看状态与保留的结果。

## 4. 来源功能联动

- 安装、更新、卸载成功后,来源功能中的目标状态应更新;批量操作只改变对应目标。
- 桶添加/移除成功后,桶集合和已加载的软件目录范围应反映新状态。
- 协助安装入口与任务信息引用同一安装任务,不得为同一次操作生成重复记录。
- 失败结果应提供可理解的原因和从来源功能重新发起操作的途径;取消不触发失败提示。

## 5. 国际化与可访问性

- 任务操作、状态与错误提示提供中英文,并随应用语言切换。
- 软件包名、桶名和日志原文保持不变。
- 键盘操作、焦点可见性和语义状态符合 `docs/design/systems/web.md`。
