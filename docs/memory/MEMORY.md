# 项目记忆

## Scoop 代理与 Git

- Scoop 的 `proxy` 配置用于 Scoop 自身的 HTTP 下载，也会传给 Scoop 内部执行的 Git 网络操作；它不会自动成为全局代理，也不会自动作用于单独启动的 Git 命令。
- 执行独立的 `fetch`、`pull`、`push`、`clone` 等联网 Git 操作时，若需要沿用 Scoop 代理，应读取其有效配置并仅传给该命令进程（例如使用进程级 HTTP(S) 代理环境变量或 Git 命令级配置），不要修改全局配置。`default`、`none` 和系统代理应按 Scoop 的实际含义处理。
- 不猜测或硬编码代理地址，不把代理凭据写入仓库、提交记录或日志输出。纯本地 Git 操作无需代理。
